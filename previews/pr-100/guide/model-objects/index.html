Model objects and parameters

What a class, Shape, component and occurrence mean.

A model is a normal Python class

Numeric class attributes become editable SolidCraft parameters when SCPF compiles a plain model class. build() returns geometry. If a file contains exactly one public class with build(), that class is the root automatically; no trailing constructor call or launcher file is needed.

from scpf import Box

class Plate:
    length = 100.0
    width = 60.0
    thickness = 10.0

    def build(self):
        return Box(self.length, self.width, self.thickness)

Run that source file directly with python -m scpf plate.py --connect. The same rule lets a reusable component file serve as its standalone model while assemblies import the exact same class. If a file contains several public model classes, SCPF deliberately does not guess: finish the script with an explicit call such as Assembly() to choose the root.

An explicit final call is also how you override root parameters for a particular run, for example Plate(width=80). Arithmetic such as self.length / 2 is preserved symbolically for supported expressions; general Python computations are not automatically made parametric.

Parameter intent is visible in the name

SCPF distinguishes three kinds of numeric class attributes. This keeps a Python build setting from looking like a native editable CAD parameter.

class Display:
    PANEL_COUNT = 5          # fixed constant
    _panel_pitch = 160.0     # Forge/build-time input
    opening_width = 844.0    # native model parameter
NameMeaningSolidCraft parameter
UPPER_CASEFixed constantNo
_lower_caseForge/build-time inputNo
lower_caseEditable model parameterYes

If a public lower-case parameter is consumed only as a concrete Python value—for example through pv()—Forge emits a ModelParameterWarning. The same warning is emitted when a parameter remains native in some geometry but is also flattened into a concrete component move() or rotation. Such a parameter is only partly associative: editing it in SolidCraft would update only part of the model. Either preserve the symbolic placement or rename an intentionally build-time input with a leading underscore.

Share one model parameter across child components

Passing a parent parameter into several component inputs keeps one native SolidCraft parameter instead of creating component-specific duplicates.

bottom = BottomBoard(corner_radius=self.corner_radius)
roof = RoofBoard(corner_radius=self.corner_radius)
bracket = Bracket(
    bracket_width=self.bracket_width,
    inside_corner_radius=self.corner_radius,
)

Here the wooden fillets and bracket inside fillet all depend on the same corner_radius. A reusable component default can also be published under an explicit shared name:

Bracket = component(
    CornerBracket,
    include={"inside_corner_radius": "corner_radius"},
)

Use a tuple such as include=("outer_corner_chamfer",) when the component should expose its own namespaced editable parameter instead.

Shape versus component occurrence

Shape describes geometry or a feature expression (Box, Hole, an extrusion). A component occurrence is one placed instance of a shared, editable model definition. Do not confuse a new occurrence with a new feature history.

from scpf import Box, component

class Block:
    def build(self):
        return Box(40, 20, 10)

BlockComponent = component(Block)
first = BlockComponent()
second = first.copy().move(x=50)
assembly = first + second

The two occurrences share the same Block definition. copy() does not duplicate its features. The compiler creates all native occurrences in place first, then sends their individual placement commands to SolidCraft. This keeps rotations and offsets independent.

Groups are actual native parent components

blocks = (first + second).group("Blocks")

Grouping changes the browser hierarchy, not the geometry's orientation. At present one shared definition cannot be split among different groups.

Important boundaries

Associative attachment is supported for a limited set of rectangular component faces. General mates, arbitrary face queries and rotational constraints are not implemented as a complete assembly solver.
