Components and assemblies

Describe reusable parts, placed copies and how they belong together.

Start from a real build

Suppose you are making a wooden display frame with eight identical corner brackets. You do not want to model eight unrelated brackets. You want to describe:

  • what one bracket looks like;
  • where eight physical copies of that bracket are used;
  • which boards and brackets together form the frame;
  • how each bracket is related to the frame.

Those four questions correspond directly to Forge's component, occurrence, assembly and attachment concepts.

Component: the reusable part design

A component describes one kind of physical part. A bracket, panel, side board or PCB enclosure is a good component candidate when you may use it more than once or want to edit it independently.

from scpf import Box, component

@component
class CornerBracket:
    width = 24.0

    def build(self):
        return Box(40, self.width, 40)

This defines the bracket design. It does not mean that only one bracket exists in the final assembly.

Occurrence: one physical use of that component

Every placed copy is an occurrence. Eight brackets in the frame means eight occurrences, while all eight still share one component definition.

first = CornerBracket()
second = first.copy().move(x=100)

Think of buying eight identical metal brackets: there is one product design, but eight physical pieces. This distinction matters because changing the component definition should not require rebuilding eight independent models.

Assembly: the construction made from parts

An assembly describes how component occurrences form a larger object. The parts remain separate; an assembly is not automatically a Boolean union.

from scpf import assembly

@assembly
class Frame:
    def build(self):
        left = SideBoard()
        right = left.copy().move(x=800)
        return left + right

The assembly can later grow to include top/bottom boards, panels and corner brackets without turning those parts into one inseparable solid.

Move or attach?

Use move() when you deliberately know an occurrence's assembly position. Use attach() when the important fact is a relationship between parts.

QuestionPrefer
“Put this reference object 200 mm to the right.”move()
“Keep this bracket on the top-left corner of the side board.”attach()
“Make five copies on a fixed pitch.”copy().move(...)
“This child must follow a parent face when its size changes.”attach()

Attachment: describe why the child belongs there

bracket = CornerBracket().attach(
    side_board,
    parent=Anchor.FRONT_TOP_LEFT,
    child=Anchor.BACK_TOP_RIGHT,
)

The parent anchor says where on the side board the relationship belongs. The child anchor says which part of the bracket is placed there. Forge then maps that intent to SolidCraft.

From the user's point of view this is the important API contract. Native SolidCraft joints are an implementation detail unless you are debugging or extending Forge.

Where should knowledge live?

A reusable component should know facts that are intrinsic to that part. An assembly should know facts that only make sense in one construction.

KnowledgeBest owner
Bracket width, hole positions, intrinsic mounting faceComponent
“This is the frame's front-top-left mounting point”Assembly
One sensor connector's local orientationComponent anchor
Which of eight brackets is used in one frame cornerAssembly

This separation keeps generic components reusable instead of filling them with names and coordinates that only make sense in one project.

Component parameter visibility

Reusable component defaults are fixed by default. They still define the component geometry, but they do not automatically clutter the design-wide SolidCraft parameter list. Publish only the defaults you actually want users to edit:

Bracket = component(
    CornerBracket,
    include=("inside_corner_radius",),
)

# Or expose every local default:
EditableBracket = component(CornerBracket, include="*")

A parent Parameter or expression passed into a component always stays symbolic, even when it is not in include. For example, Bracket(inside_corner_radius=self.corner_radius) reuses the parent design's corner_radius; it does not create a separate CornerBracket_inside_corner_radius parameter.

Occurrence placement

copy() in Python retains the source's intended position and orientation. move() then adds the given displacement. For example, moving a copy by X=120 after its source already sits at X=50 makes the copy's intended X position 170. This is normal Python-side behavior. When compiling, SCPF first creates all native occurrences at the origin and asks SolidCraft to position each one once. No previous native transform needs to be undone, and no inverse matrix is calculated.

center = BeamComponent()
array = center
for x in (-240, -120, 120, 240):
    array = array + center.copy().move(x=x)

Component attachment

right = BeamComponent().attach(
    left, parent=Anchor.RIGHT, child=Anchor.LEFT
)

marker = Marker().attach(
    frame,
    parent=Anchor.FRONT_TOP_RIGHT,
    child=Anchor.BACK_TOP_RIGHT,
)

attach() is the public Forge relationship between reusable components. Anchor selects the attachment reference: a supported face, or one of the eight rectangular corners such as FRONT_TOP_RIGHT. Corner anchors compile to native SolidCraft edge/corner origins, so they follow dimension changes in a saved design.

Associative in-plane attachment offset

attach(offset=(u, v)) moves the child within the attachment plane. Numeric values and parameter expressions are both supported. Forge lowers a non-zero or symbolic in-plane offset to a native planar joint and keeps u and v as SolidCraft joint values, so they are re-evaluated when their parameters change.

wood = Parameter("wood_thickness", 18)

bracket = Bracket().attach(
    side,
    parent=Anchor.FRONT_TOP_LEFT,
    child=mount,
    offset=(0, -wood + 12),
    gap=-12,
)

offset is independent of gap: the two offset values move in the attachment plane, while gap remains the normal distance between the two references. On a rectangular corner origin, the second planar value follows the selected vertical corner edge; its sign is defined by that corner frame rather than by world Z.

Assembly-owned named anchors

When a datum belongs to the meaning of an assembly rather than to a generic component, keep it on the assembly with with_anchor(). The anchor stores the target occurrence plus its attachment reference. Consumers resolve it by name with anchor().

frame = (left + right + bottom).with_anchor(
    "front_top_left",
    left,
    AnchorTopology(
        edge=(-6, 0, 181),
        on=(0, 0, 181),
        corner=(-6, 0, 362),
        z=(0, 0, -1),
        x=(1, 0, 0),
    ),
)

parent = frame.anchor("front_top_left")
bracket = CornerBracket().attach(
    parent.target,
    parent=parent.reference,
    child=bracket_reference,
)

This keeps a generic Board or CornerBracket free of application-specific anchor names while a higher-level frame can expose semantic datums such as front_top_left.

An assembly anchor may also carry its own symbolic offset=(u, v). Consumers can combine that semantic offset with a fixed local correction and pass the result to attach(offset=...). This is useful when an assembly datum follows a frame parameter such as wall thickness while the reusable part keeps a fixed mounting correction.

AnchorFrame: point plus orientation

An AnchorFrame describes one local attachment coordinate frame. origin gives the local point; z gives the attachment normal and x fixes the rotation around that normal. Use it when a single point or rectangular Anchor is not enough to describe how the occurrence must be oriented.

from scpf import Anchor, AnchorFrame

mount = AnchorFrame(
    origin=(0, 0, -12),
    z=(0, 1, 0),
    x=(0, 0, -1),
)

bracket = CornerBracket().attach(
    side_board,
    parent=Anchor.FRONT_TOP_LEFT,
    child=mount,
)

There are two ownership patterns. If the datum is an intrinsic part of a reusable component, expose it with anchors() and refer to it by name. If the frame exists only because of a particular assembly or mounting choice, construct the AnchorFrame in that assembly and pass it directly to attach(). This keeps application knowledge out of the generic component definition.

@component
class Sensor:
    def anchors(self):
        return {
            "connector": AnchorFrame(
                origin=(12, 0, 4),
                z=(1, 0, 0),
                x=(0, 0, 1),
            )
        }

    def build(self):
        return Box(24, 12, 8)

sensor = Sensor().attach(panel, child="connector")

For an unrotated occurrence, Forge lowers an AnchorFrame directly into the native joint.create reference as point, z and x; it does not create a persistent visible joint.origin. Named frames on explicitly rotated occurrences currently use the native origin fallback so SolidCraft owns the transform. A direct AnchorFrame on an explicitly rotated occurrence is not supported yet.

AnchorTopology: follow an edge or corner

AnchorTopology is a named component datum that stays attached to native SolidCraft topology. edge picks an edge, on selects its adjacent planar face and corner optionally chooses one endpoint. The coordinates are selection picks; SolidCraft keeps the selected edge, face and endpoint by topology name as the design changes.

from scpf import AnchorTopology, Box, component

@component
class Board:
    def anchors(self):
        return {
            "mount": AnchorTopology(
                edge=(-20, 50, 5),
                on=(-20, 50, 10),
                corner=(-20, 0, 5),
                z=(0, 1, 0),
                x=(0, 0, 1),
            )
        }

    def build(self):
        return Box(40, 100, 20)

This is useful for references such as the straight tangent edge beside a fillet: if dimensions move that edge, the joint can follow it without freezing the original XYZ point. The current implementation supports named or direct AnchorTopology values on non-rotated occurrences. A direct topology anchor is useful when the datum belongs only to one assembly rather than to the reusable component. SCPF deliberately does not transform topology picks itself.

SolidCraft joints remain an internal implementation detail; Forge does not expose a separate public Joint object.

What to test in an assembly

Check the native command list for one component.create per shared definition, expected occurrence.copy counts, and native translate, axis and angle parameters for rotated occurrences. Separately verify native SolidCraft geometry and its bounding dimensions before trusting an assembly image.
