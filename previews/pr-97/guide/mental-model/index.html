How to think about Forge

The small set of concepts you need before learning the API.

Start with the thing you want to build

You do not need to think in SolidCraft commands, transformation matrices or joint internals to use Forge. Start by asking a simpler question: what are the physical parts, and how are they related?

For a small frame with four corner brackets, for example, you might have:

  • two side boards;
  • a top and bottom board;
  • one reusable corner-bracket design;
  • eight placed copies of that bracket.

Forge turns that description into native SolidCraft geometry and assembly relationships.

Model: one thing you can build

A model is a Python class with a build() method. It describes one piece of geometry or one composed result.

class Plate:
    width = 100.0
    height = 60.0
    thickness = 10.0

    def build(self):
        return Box(self.width, self.height, self.thickness)

The public dimensions can become editable CAD parameters. You normally do not need to write SolidCraft commands yourself.

Component: a reusable physical part

A component is a model that represents a reusable part. Think of a bracket, panel, beam or PCB enclosure. If you need the same part five times, you still want one definition of the part.

@component
class Bracket:
    def build(self):
        return Box(40, 20, 10)

Changing the component definition changes what every occurrence of that part represents.

Occurrence: one placed copy of a component

An occurrence is one use of a component inside a larger design. It has its own position and orientation, while sharing the same component definition.

first = Bracket()
second = first.copy().move(x=80)

This is similar to putting two identical purchased brackets on a workbench: they are two physical instances of the same part design.

Assembly: parts that belong together

An assembly combines component occurrences into a larger construction. An assembly is not one fused blob of geometry. The parts remain separate, reusable objects with relationships between them.

@assembly
class Frame:
    def build(self):
        left = SideBoard()
        right = left.copy().move(x=800)
        return left + right

An assembly can itself expose useful attachment locations for something that will be mounted to the complete frame.

Anchor: a meaningful place and direction

An anchor tells Forge where a relationship belongs. A simple anchor can mean “the right face” or “the front-top-left corner”. More advanced anchors can also describe orientation.

parent=Anchor.FRONT_TOP_LEFT
child=Anchor.BACK_TOP_RIGHT

This is more useful than saying “put it at X=412, Y=-6, Z=362”, because a semantic anchor can keep referring to the same face or corner when dimensions change.

Important: an anchor should be thought of as a local attachment reference, not merely a world XYZ point. For oriented attachments, its local directions matter too.

Attachment: the relationship between two anchors

attach() says that one component occurrence belongs relative to another one. You choose a parent anchor and a child anchor; Forge converts that relationship into the appropriate native SolidCraft representation.

bracket = Bracket().attach(
    side,
    parent=Anchor.FRONT_TOP_LEFT,
    child=Anchor.BACK_TOP_RIGHT,
)

From a user point of view, the important statement is simply: “attach this bracket here using this side of the bracket.” You should not need to design the underlying SolidCraft joint yourself.

Gap, offset and orientation are different ideas

Once two anchors are related, additional values may refine that relationship. Keep these concepts separate:

ConceptMeaning
gapDistance along the attachment normal
offset=(u,v)Displacement inside the local attachment plane
orientation / frameWhich way the attached part faces
world moveExplicit placement in assembly X/Y/Z coordinates

These are intentionally not interchangeable. A local attachment offset is not automatically a world-X or world-Z movement.

Parameters: dimensions you expect to edit later

A parameter is a value that should remain meaningful after the Python model has been compiled. If a frame width changes from 800 to 900 mm, an attached part should ideally follow its semantic anchor rather than keep an old hard-coded coordinate.

This is why Forge qualification tests do more than check the initial picture: important cases also edit the saved SolidCraft parameters and verify that relationships still solve correctly.

What SolidCraft does underneath

Forge is a description and compilation layer. SolidCraft remains the CAD engine. Forge may lower your intent to sketches, extrusions, component occurrences, joint origins or native joints, but those are implementation details unless you are debugging or extending Forge.

The later chapters explain those details where they are useful. For normal model writing, keep the simpler hierarchy in mind:

model
  └─ component definition
       └─ occurrences
            └─ assembly
                 └─ anchors
                      └─ attachments
