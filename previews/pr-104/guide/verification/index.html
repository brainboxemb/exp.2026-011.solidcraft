Verification and API boundaries

Python unit tests, native JSON plans and mechanical evidence.

Unit tests for Python behavior

The library's tests under scpf/tests/ cover model objects, feature compilation, reusable components and rotation validation. For example, an occurrence rotation test checks that the compiler emits one occurrence.move with the expected native parameters.

python -m unittest discover -s scpf/tests -v

Test compiled native commands

Compare the generated command structure with explicit expectations, not only with a count of operations. Tests should check component names, requested positions, the orientation axis and angle, and feature ordering. A regression can preserve a known good JSON fixture when command ordering is part of the contract.

Native geometric verification

The CAD model repository runs a separate SolidCraft CLI workflow for native geometry, editable history, STEP output, measurements and screenshots. Read the saved SolidCraft occurrence transforms, not just whether a command ran successfully. A valid Python object or syntactically valid command plan is not evidence that the final solid occupies the correct plane or has no collision.

Keep implementation and docs in sync

When placement syntax changes, add tests for the exact generated native commands before documenting it as supported. Named principal-axis rotation is supported; chained rotations are still not.

For a plain-language explanation of the implementation and its boundaries, read How SCPF works (without building a second CAD engine).
