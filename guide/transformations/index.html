Transformations and orientation

Coordinate systems, movement, rotation, copies and what is not yet supported.

First choose the coordinate system

SolidCraft models are three-dimensional: X, Y and Z are axes, not synonyms for left, up and front in every project. The conventional Box base is in XY and its height extends along +Z. A portrait HUB75 module may be authored with its large face in XY, then placed upright in the assembly's XZ plane.

Differentiate definition coordinates (how one component is built) from assembly coordinates (where an occurrence is placed). A camera rotation is only a change of view; it does not change any of these coordinates.

Move: translation

from scpf import Box

body = Box(40, 20, 10)
shifted = body.move(x=10, y=0, z=25)

For supported CSG shapes, move() translates the full CSG expression. A feature-based Plate body cannot always be freely moved using the same method. Component occurrences have their own placement move(), which adds the requested displacement.

from scpf import component

class Panel:
    def build(self):
        return Box(160, 320, 14.5)

PanelComponent = component(Panel)
first = PanelComponent()
right = first.copy().move(x=160)

Rotate: axis and angle on a component occurrence

In the current implementation, rotate() belongs to a component occurrence and accepts an XYZ direction tuple and an angle in degrees. It rotates the placement about the component's local origin. The shared component definition is not modified.

from scpf import X, Y, Z

upside_down = first.copy().rotate(Z, 180)
upright = first.copy().rotate(X, 90)

# Explicit XYZ tuple form remains valid:
sideways = first.copy().rotate(axis=(0, 1, 0), degrees=90)

The first rotates about Z; the second rotates about X. A rotation around X can convert a face authored in XY into a vertical XZ face. The direction of the depth axis changes too.

Critical: rotate sets an orientation; it does not compose

# NOT two successive rotations in current SCPF:
panel = first.rotate(axis=(1, 0, 0), degrees=90)
panel = panel.rotate(axis=(0, 1, 0), degrees=180)

The second call replaces the first occurrence rotation. It does not apply a second rotation on top of the first. A model that appears to lie flat after a second rotation can be caused by this rule. SCPF currently supports one absolute axis-angle orientation per occurrence, not chained Euler rotations.

For a final orientation involving several conceptual turns, give SCPF one axis-angle orientation. SolidCraft performs the native rotation; SCPF does not build its own rotation matrices. Verify the saved native geometry to check which direction is up.

Named axis rotation

The exported X, Y and Z tokens can be passed directly to occurrence rotation. Prefer rotate(Y, 90) when a principal-axis turn is all that is needed. The explicit axis=(x,y,z), degrees=… form remains available for arbitrary axis-angle placement.

Cylinder orient is a different operation

from scpf import Cylinder, X, Y, Z

tool = Cylinder(d=10, h=30).orient(X, Y, Z)

orient() is currently restricted to Cylinder shapes and their supported CSG compilation. It does not mean arbitrary model rotation. Do not substitute orient(Z) for a component occurrence's rotate(axis=(0,0,1), degrees=…).

Copies are independent placements

One component definition describes the shape and its editable features. Every occurrence says where one copy belongs in the assembly. Several occurrences reuse the same definition.

first = PanelComponent().move(z=160).rotate(axis=(1, 0, 0), degrees=90)
second = first.copy().move(x=160)
screen = first + second

In Python, copy() inherits the desired placement: second keeps the 90° rotation and adds 160 mm to X. In the generated command sequence, however, SCPF makes both native occurrences at the origin before moving either one. It then asks SolidCraft to place each one. This prevents a copy from accidentally inheriting an already-applied native rotation or offset.

What SCPF actually sends to SolidCraft

The sequence below is deliberately simple: create one component, copy it once, then ask SolidCraft to place both occurrences. The editable shape features are omitted here for clarity.

{
  "commands": [
    {"command":"component.create","params":{"name":"Panel"}},
    {"command":"occurrence.copy","params":{"component":"Panel"}},
    {"command":"occurrence.move","params":{
      "occurrence":"Panel:1",
      "translate":[0,0,160],
      "axis":[1,0,0],
      "angle":"90 deg",
      "move_grounded":true
    }},
    {"command":"occurrence.move","params":{
      "occurrence":"Panel:2",
      "translate":[160,0,160],
      "axis":[1,0,0],
      "angle":"90 deg"
    }}
  ]
}

SolidCraft 0.30.1 understands the native translate, axis and angle parameters. SCPF does not calculate transformation matrices. The newer to placement field is not supported by 0.30.1; using it previously left a panel flat without reporting an error.

Passing a command-plan test is not enough to prove the CAD is right. The CAD project's native tests also inspect the rotations and positions saved in SolidCraft's own design, and front/rear screenshots help verify the result visually. A camera change does not rotate the actual panel geometry.
